## Critical issue found + fixed (Phase 17)

### Symptom

The pytest autouse fixture `_ensure_fixture_cache()` was unconditionally
overwriting the real crawler cache with synthetic 55-item data on every
`pytest tests/` invocation. This made it impossible to spot-check a single
test against real data without losing 2.9MB of fresh crawler output.

### Root cause

`tests/conftest.py:26` had `@pytest.fixture(autouse=True) def
_ensure_fixture_cache()` which fired for every test. Combined with
`loader.invalidar_cache()` from `test_data_loader.py:101` deleting the
cache mid-suite, real data was destroyed on the next autouse rebuild.

### Fix

Two-tier fixture system in `tests/conftest.py`:

1. **`real_cache_snapshot` (session-scoped, autouse)**:
   - At session start: capture `app/leb/cache/leiloes_reais.json` → `.real_snapshot.json`
     (only if real cache present + no existing snapshot)
   - At session end: restore snapshot back over `leiloes_reais.json`
   - Snapshot persists between pytest invocations on the same host

2. **`_ensure_fixture_cache` (function-scoped, autouse, CONDITIONAL)**:
   - Skips rebuild when cache is real-shaped (>=100 items, moradaDistrito +
     _categoria present), age <= 7 days
   - Rebuilds only when cache is missing / invalid / synthetic / stale

### Verification

| Property | Before fix | After fix |
|---|---|---|
| Cache after full pytest run | Synthetic 55 items | **Real 2981 items preserved** |
| Snapshot file | n/a | 2959642 bytes (`.real_snapshot.json`) |
| Tests | 61 passing | 61 passing |
| Coverage | 74.06% | **74.30%** (geo_portugal improved 77.4% → 83.9% with real-data) |
| Phase 12 root cause #c isolation | Preserved | **Preserved** (rebuild still happens for synthetic-shape cache) |

## Critical bugs/high-risk issues

### Bug 1 (CRIT for dev workflow): Port 8001 orphan

The very first backend probe in this analysis was v0.2.0 (ancient, leftover
from before the redesign). It returned HTTP 500 on `/api/kpis`. The orphan
process (PID 85788) didn't exist as a real process — only the socket was
held by the kernel.

**Workaround:** started new backend on :9001.
**Permanent fix needed (Phase 18+):** add a pre-dev-startup hook that checks
for stale `:8001` sockets (`Get-NetTCPConnection -LocalPort 8001 -State
Listen`) and refuses to start if found. Or: change the canonical dev port
to a high-numbered one (9001+) and use `npm run dev:check-port` as the
gate. Currently no automation catches this — only manual terminal inspection.

### Bug 2 (CRIT for agent subshells): WinError 10106 on uvicorn spawn

The hermes-agent venv's Python fails to spawn uvicorn with `OSError:
[WinError 10106] The requested service provider could not be loaded or
initialized` deep in `_overlapped`. Known issue with Winsock initialization
when Python is spawned from a sandboxed process.

**Workaround:** use OS-level Python (`C:\Users\lion_\AppData\Local\Microsoft\WindowsApps\python.exe`)
with `PYTHONPATH=""`. Works.

**Permanent fix needed:** the agent-sandbox Python should be patched to
initialize Winsock correctly OR the agent should auto-detect and swap to
the OS Python for server-spawning operations.

### Bug 3 (MEDIUM): Hardcoded port 8001 throughout

**Where:** `vite.config.ts:17`, `e2e/ui-ux-validation.spec.ts` (5+ places),
plus implicit references in console-error logging and README.

**Risk:** if backend migrates to a different port, tests silently hit the
wrong port. The orphan-port bug is the same class of issue.

**Permanent fix needed (Phase 18+):** introduce `BACKEND_PORT` env var,
document the env var convention, update tests + CI + docs to use it.
Add `npm run dev:port-check` that fails fast when 8001 is owned by a stale
process.

### Bug 4 (LOW): Crawler path hardcoded to relative location

`app/leb/data/crawler_eleiloes.py:8`: `CACHE_PATH = Path(__file__).parent.parent
/ "cache" / "leiloes_reais.json"`. Correct now (resolves to `app/leb/cache/`)
but if the file is moved back to `vendor/leiloes-pt-data/data/`, the cache
writes go to the wrong location with no error.

**Permanent fix needed:** add a defensive check at module load: assert
`__file__.parent.parent.name == "leb"` else raise with a clear error message.
Or hardcode the absolute path passed at build time.

## Suggestions (improvements)

### Suggestion A: Expand vitest coverage from 1 file to multiple

Currently measured: `src/lib/ui.tsx` (96.18%).

**Recommended order (highest value first):**

1. `src/lib/api.ts` (321 stmts) — biggest impact, axios mocks are
   straightforward (`vi.mock('axios')` or MSW)
2. `src/hooks/useFocusTrap.ts` + `useKeyboardNav.ts` (142 stmts total) —
   pure hooks, RTL render covered already
3. `src/components/KPICard.tsx` + `LanguageSwitcher.tsx` + `Toast.tsx` —
   ~250 stmts, RTL renders, fast to test
4. `src/lib/Drawer.tsx` (117 stmts, Leaflet-heavy) — last, needs happy-dom
   + complex Leaflet mock

Push `src/lib/` + `src/components/` + `src/hooks/` coverage to 70%+ before
opening routes/components to measurement (each route drags coverage down
without proportional value).

### Suggestion B: Cache scheduling via cron

Real crawler (2981 items, 18 districts) takes ~30 seconds on a stable network.
Currently run on-demand only — cache goes stale within 24h and Phase 8's
"STALE" banner appears (working correctly).

**Recommendation:** add a daily cron via `hermes cronjob` (`30 8 * * *`) that
runs `python -m app.leb.data.crawler_eleiloes` and commits a cache refresh
if delta is significant (>50 new items). Keeps cache fresh for live
exploration.

### Suggestion C: Mutation testing on Linux CI cron

The Phase 16 scaffold does nothing on this Windows host. On Linux
ubuntu-latest runners, cosmic-ray works.

**Recommended:** add a 5th CI job `mutation-suite` that:
- Runs weekly only (cron schedule, not on every push — 5-30min per module)
- Targets `app/leb/data/loader.py` first (smallest module, most critical)
- Posts surviving-mutant report to GitHub summary
- Failing mutants becomes a test-writing sprint guide

### Suggestion D: Playwright flake detection

58 passed + 1 skipped in this run, no flakes observed. But there's no
flake tracking over time.

**Recommended:** add a CI job `playwright-flake-detect` that runs each
test 3x and flags non-deterministic failures. Tests with even 1/3 failure
get quarantined to a `flaky` tracker issue.

### Suggestion E: TypeScript strict check

`tsconfig.json` should be verified for `strict: true`. Currently
`npm run type-check` is in scripts but the TS config details weren't
audited in this session. Worth a Phase 18 audit task.

### Suggestion F: Deprecation swap (datetime.utcnow → utc-aware)

`tests/test_data_loader.py:84-88`: replace `datetime.utcnow()` with
`datetime.now(timezone.utc)` to pre-empt Python 3.13+ failure mode.
No behavior change.

### Suggestion G: Coverage artifact retention (already noted)

Bump `actions/upload-artifact@v4.retention-days` from 7 to 30 on the
coverage-report and frontend-coverage artifacts in `.github/workflows/ci.yml`.
